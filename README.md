# Bombermaaan

Bombermaaan is a classic Bomberman-style game project originally started by Thibaut Tollemer in July 2000. It is a local multiplayer game with support for up to eight players, computer opponents, custom levels, bombs, items, and several game modes.

## Repository layout

- `src/` — game source code and platform-specific build files
- `levels/` — shipped level files
- `scripts/` — build and level utility scripts
- `docker/` — Linux and Windows container build definitions
- `src/native-switch/` — Nintendo Switch port
- `docs/` — legacy documentation and level format information
- `images/` — project artwork and icons

## Building with Docker

The platform builds use containerized toolchains, so host-installed SDL, SDL_mixer, MinGW, and Switch development libraries are not required.

Docker or Podman is required. The scripts automatically select Podman when available, otherwise Docker, unless `CONTAINER_ENGINE` is set.

### Linux

```sh
./scripts/docker-build-linux.sh
```

The builder uses `docker/Dockerfile.linux` and creates:

```text
build-linux/Bombermaaan-linux.zip
build-linux/Bombermaaan-linux/
```

Run the packaged game with:

```sh
./build-linux/Bombermaaan-linux/launch.sh
```

Useful options:

```sh
JOBS=4 ./scripts/docker-build-linux.sh
IMAGE_PULL=1 ./scripts/docker-build-linux.sh
CONTAINER_ENGINE=podman ./scripts/docker-build-linux.sh
```

### Windows

```sh
./scripts/docker-build-windows.sh
```

The builder uses `docker/Dockerfile.windows`, MinGW-w64, SDL 1.2, SDL_mixer, and the bundled DirectX SDK files. It creates:

```text
build-windows/Bombermaaan-windows.zip
build-windows/Bombermaaan-windows/
```

The build log is written to `docker-build-windows.log`. To force a fresh builder image:

```sh
./scripts/docker-build-windows.sh clean-image
```

### Nintendo Switch

```sh
./scripts/docker-build-switch.sh
```

The Switch build pulls and uses the official:

```text
docker.io/devkitpro/devkita64:latest
```

The Switch build mounts the repository and the root `levels/` directory into the container. Build outputs are generated by `src/native-switch/build.sh`, including the Nintendo Switch `.nro` artifact.

Useful options:

```sh
SKIP_IMAGE_PULL=1 ./scripts/docker-build-switch.sh
CONTAINER_ENGINE=podman ./scripts/docker-build-switch.sh
CONTAINER_USE_HOST_USER=1 ./scripts/docker-build-switch.sh
```

## Local Linux build

A local build is also possible when the required development libraries are installed:

```sh
make -C src
```

The executable is created at `src/Bombermaaan/Bombermaaan`. Depending on the environment, the runtime library path may need to include `src/RESGEN`:

```sh
LD_LIBRARY_PATH=src/RESGEN src/Bombermaaan/Bombermaaan
```

The Docker build is recommended for reproducible builds.

## Running the game

The game reads levels from a `Levels` directory next to the executable. The packaged builds already contain the levels from the repository's root `levels/` directory.

Configuration and log files are stored in the platform-specific user data directory by default. The original command-line options include:

- `--help` — show copyright and license information
- `--use-appdata-dir` — use `%APPDATA%/Bombermaaan` on Windows
- `--ignore-home-dir` — use the local directory instead of `~/.Bombermaaan` on Linux

Custom levels can be added to the corresponding `Levels` directory.

## Controls

### During a match

| Input | Default |
|---|---|
| Keyboard 1 movement | `8 / 5 / 4 / 6` |
| Keyboard 1 actions | `PageUp / Home` |
| Keyboard 2 movement | `R / F / D / G` |
| Keyboard 2 actions | `2 / 1` |
| Keyboard 3 movement | `I / K / J / L` |
| Keyboard 3 actions | `8 / 7` |
| Keyboard 4 movement | `H / N / B / M` |
| Keyboard 4 actions | `5 / 4` |
| Keyboard 5 movement | Arrow keys |
| Keyboard 5 actions | Right Control / Right Shift |
| Joystick movement | D-pad or left stick |
| Joystick actions | Buttons 1 and 2 |
| Pause | `Escape` or `P` |

Movement is restricted to the horizontal and vertical block grid; diagonal input is resolved to the dominant axis.

### Menus

- Up/Down — select an item
- Left/Right — change a value
- Backspace — previous screen
- Return, Space, or Enter — continue
- Escape — close the menu or pause dialog

### Display shortcuts

- `F1` — 320x240 mode where available
- `F2` — 512x384 mode where available
- `F3` — 640x480 mode
- `F4` — windowed mode
- `F5` — 640x480x32 mode
- `Ctrl+F12` — exit quickly without confirmation
